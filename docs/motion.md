# Движение в интерфейсе

Спецификация анимаций в панели приложения.

> **Состояние: реализовано.** Уровень движения переключается в окне настроек — *Settings → Motion*
> (Off / Subtle / Expressive), хранится в `UserDefaults` под ключом `motionLevel`, по
> умолчанию **Subtle**. Системный Reduce Motion действует поверх выбора: движение
> заменяется кроссфейдом, длительности сокращаются до 0.6. Единственный вентиль —
> `Sources/Motion.swift`; ни один вызывающий код не хранит собственных длительностей.

## Что изменилось: меню стало окном

До версии 0.13.0 выпадашка была `NSMenu`, и это ставило жёсткие границы. Они записаны
здесь потому, что объясняют, почему часть анимаций раньше была невозможна, а теперь есть:

- **`NSMenu` не переразмечается, пока открыто.** Высота окна меню фиксировалась при
  открытии, поэтому аккордеона — клик по серверу, под ним выезжают строки инструментов —
  в том каркасе быть не могло.
- **Строку без своего `NSView` анимировать было нечем**: обычные пункты меню рисует AppKit.

Сейчас панель — своё безрамочное окно (`Sources/PanelWindow.swift`) с содержимым на
SwiftUI. Обоих ограничений больше нет: высота окна следует за содержимым, раскрытие строк
работает, и любой элемент панели — обычная вьюха, которую можно анимировать.

## Почему это почти ничего не стоит

Анимация уходит в render server: процесс делает работу **один раз**, на коммите, дальше
кадры интерполирует система.

Отсюда три класса стоимости:

| Класс | Что это | Цена |
|---|---|---|
| **RS** | `CABasicAnimation` на слое окна; SwiftUI `withAnimation` / `.animation` | коммит + 0 за кадр |
| **C** | сборка анимаций при открытии панели | десятки мкс на анимацию |
| **PF** | `Timer` + перерисовка каждый кадр, изменение размера `NSVisualEffectView` | главный поток каждый кадр — **запрещено** |

Суммарный бюджет: **< 1.5 мс на открытие панели**, **0 при закрытой панели**.

## Анимации

### Появление панели

| | |
|---|---|
| Файлы | `Sources/PanelWindow.swift`, `Motion.appear` |
| Свойства | `opacity`, `transform` — scale 0.96 плюс сдвиг 8 pt вниз |
| Тайминг | 190 мс |
| Кривая | easeOut |
| Класс | RS, ~0.05 мс коммит |

Панель разворачивается из строки меню: сдвиг направлен вниз, от иконки, за которую она
подвешена. Core Animation, а не SwiftUI, потому что анимируется слой самого окна —
он снаружи вьюхи, которую окно содержит.

### Переключение вкладки и раскрытие строки

| | |
|---|---|
| Файлы | `Sources/PanelView.swift` (`.animation(…, value:)`) |
| Тайминг | 180 мс, easeOut |
| Класс | RS |

Это ровно то, чего не могло быть в меню. Клик по шеврону сессии или сервера меняет
`store.expanded`, панель перерисовывается с новой высотой, окно следует за ней
(`windowDidResize` заново прибивает верхний край к иконке).

### Полосы лимитов и контекста

| | |
|---|---|
| Файлы | `Sources/PanelTheme.swift` (`PanelBar`) |
| Класс | RS |

Ширина заливки считается так же, как у полосок рядом с иконкой в строке меню
(`Gauge.fillWidth`): пол в один физический пиксель, чтобы «остался 1%» не выглядел как
«пусто». Полоса не пружинит: 93% не имеют права на миг показать 98%.

### Лесенка строк — только на уровне Expressive

| | |
|---|---|
| Файлы | `Sources/Motion.swift` (`PanelEntrance`) |
| Тайминг | 230 мс, сдвиг 16 мс, потолок 180 мс суммарно |
| Свойства | `opacity`, сдвиг по вертикали −5 pt |
| Класс | C, ~0.9 мс на 20 строк |

**Не по умолчанию.** Потолок нужен, чтобы двадцать строк MCP не продолжали появляться
через треть секунды после того, как панель попросили: это читается как подтормаживание,
а не как оживление. Счёт идёт сквозь весь список, а не по группам — иначе первая строка
новой группы села бы на последнюю строку предыдущей.

## Правила

1. **Ни одного `Timer` ради анимации.** Всё, что движется, — либо `CAAnimation`, либо
   SwiftUI-анимация. Единственный исключённый случай — системный индикатор
   `ProgressView`, который рисует и крутит AppKit, а не мы.
2. **Ноль работы при закрытой панели.** Все анимации одноразовые, бесконечных повторов нет.
3. **Reduce Motion уважается всегда.**
   `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` заменяет движение
   на кроссфейд, а не отключает его насухо: смена состояния должна оставаться видимой.
4. **Числа не врут по дороге.** Никакого перелёта на шкалах.
5. **Размер `NSVisualEffectView` не анимируется.** Прозрачность — можно,
   геометрию — нет: `.behindWindow` пересчитывает блюр каждый кадр.

## Как проверить

| Что | Как | Порог |
|---|---|---|
| Простой | `sudo powermetrics --samplers tasks -n 5 -i 1000`, панель закрыта | совпадает с текущим до шума измерения |
| Открытие панели | Instruments → Time Profiler, 30 открытий подряд, время в `openPanel` | рост ≤ 1.5 мс на открытие |
| Пропуск кадров | Instruments → Animation Hitches, проход по 20 строкам MCP | ноль hitch'ей |

Снимать до и после изменений в движении.
