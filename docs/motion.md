# Движение в интерфейсе

Спецификация анимаций раскрытия для меню и карточек. Живые макеты с теми же
таймингами — `docs/motion-mockups.html` (открывается в браузере).

> **Состояние: реализовано.** Уровень движения переключается в меню — *Options → Motion*
> (Off / Subtle / Expressive), хранится в `UserDefaults` под ключом `motionLevel`, по
> умолчанию **Subtle**. Системный Reduce Motion действует поверх выбора: движение
> заменяется кроссфейдом, длительности сокращаются до 0.6. Единственный вентиль —
> `Sources/Motion.swift`; ни один вызывающий код не хранит собственных длительностей.

## Что можно анимировать, а что нет

Меню приложения — `NSMenu`, а не своё окно. Это задаёт границы, и они уже
записаны в коде:

- **`NSMenu` не переразмечается, пока открыто** (`Sources/Menu.swift:23`,
  `Sources/MCPMenu.swift:172`). Классического аккордеона — клик по серверу, под
  ним выезжают строки инструментов — в этом каркасе быть не может: высота окна
  меню фиксируется при открытии.
- **Открытие самого меню анимирует macOS**, переопределить это нельзя.
- **Строку без своего `NSView` анимировать нечем**: обычные пункты меню рисует
  AppKit.

Поверхность для раскрытия у приложения уже есть — `HoverCard`
(`Sources/ToolCard.swift`): borderless-окно уровня `.popUpMenu`, в котором
показываются детали сессии (`SessionCard`) и детали MCP-инструмента
(`ToolCard`). Это настоящее `NSWindow`, там доступна вся Core Animation.
Раскрытие живёт там.

## Почему это почти ничего не стоит

`CAAnimation` уходит в render server: процесс делает работу **один раз**, на
коммите, дальше кадры интерполирует система. Комментарий в
`Sources/MenuRows.swift:5` фиксирует это как причину, по которой пружина
тумблера вообще играет во время menu tracking.

Отсюда три класса стоимости, которыми размечено всё ниже:

| Класс | Что это | Цена |
|---|---|---|
| **RS** | `CABasicAnimation` / `CASpringAnimation` на `opacity`, `transform`, `bounds`, `backgroundColor` | коммит + 0 за кадр |
| **C** | сборка анимаций при открытии меню | десятки мкс на анимацию |
| **PF** | `Timer` + `needsDisplay`, `NSWindow.setFrame(display:animate:)`, изменение размера `NSVisualEffectView` | главный поток каждый кадр — **запрещено** |

Ориентир класса PF — нынешний `SpinnerView` (таймер 20 Гц). Ни одна новая
анимация не должна попасть в этот класс.

Суммарный бюджет: **< 1.5 мс на открытие меню**, **0 при закрытом меню**.

## Анимации

### HoverCard — раскрытие деталей

| | |
|---|---|
| Файлы | `Sources/ToolCard.swift`, `Sources/SessionCard.swift` |
| Триггер | наведение на строку, задержка 300 мс (уже реализована) |
| Свойства | `opacity`, `transform` — scale 0.96 плюс сдвиг 10 pt в сторону строки |
| Тайминг | окно 190 мс; блоки 240 мс со сдвигом 26 мс; полоса контекста 600 мс |
| Кривая | easeOut; полоса — пружина ζ 0.8 |
| Скрытие | 120 мс, только `opacity`, `orderOut` **после** завершения |
| Класс | RS, ~0.4 мс коммит |

Карточка разворачивается со стороны своей строки: масштаб идёт из центра, а сдвиг
на 10 pt направлен обратно к строке — вправо, если карточка встала слева, и влево,
если справа. Именно сдвиг, а не `anchorPoint`: `anchorPoint` слоя `contentView`
сместил бы само окно, и его пришлось бы компенсировать позицией на каждом показе.

Скрытие анимирует только прозрачность, и модельное значение `opacity` служит
признаком: если за время затухания курсор перешёл на соседнюю строку, `place()`
вернул 1, и completion-блок не убирает окно, которое уже снова на экране.

Единственная строка, которую стоит померить на Intel: `.behindWindow`-блюр
карточки пересчитывается все 190 мс показа. Если Animation Hitches покажет
пропуски — сократить показ до 150 мс.

### Полосы лимитов — заполнение при открытии

| | |
|---|---|
| Файлы | `Sources/LimitRows.swift` |
| Триггер | `viewDidMoveToWindow`, раз на открытие меню |
| Свойства | `bounds.size.width` слоя заливки |
| Тайминг | 620 мс, сдвиг 70 мс между строками |
| Кривая | пружина ζ 0.8 — **без перелёта** |
| Класс | RS, ~0.1 мс коммит |

Заливка переезжает из `draw(_:)` в `CALayer` внутри слоя-маски со скруглением.
Ширина по-прежнему берётся из `Gauge.fillWidth` — договор «строка в меню и
полоски у иконки не расходятся» остаётся дословно тем же, включая пиксельный
пол. Анимируется ширина, **не** `transform.scale.x`: масштаб растянул бы и этот
пол.

### Строки — подсветка, шеврон, тумблер

| | |
|---|---|
| Файлы | `Sources/MenuRows.swift`, `Sources/MCPMenu.swift` |
| Подсветка | вход **0 мс**, выход 90 мс, только `opacity` |
| Шеврон | `transform.translation.x` +2 pt, 200 мс, на hover |
| Ручка тумблера | сплющивание 15 → 18 → 15 pt на ходу, поверх существующей пружины |
| Класс | RS, ~0.02 мс на жест |

Асимметрия подсветки намеренная: в системных меню выделение не догоняет курсор,
а мягкое затухание убирает мерцание при быстром проходе по списку.

### Баннер обновления

| | |
|---|---|
| Файлы | `Sources/MenuRows.swift` (`UpdateBannerView`) |
| Появление | 300 мс, scale 0.97 → 1, пружина ζ 0.8 |
| Прогресс | полоса под текстом стадии, линейно к следующему значению |
| Нажатие | пилюля scale 0.96 на 80 мс |
| Класс | RS, ~0.05 мс коммит |

Полоса закрывает настоящую дыру: сейчас «Downloading… 43%» меняется числами, и
между обновлениями стадии ничего не движется — медленная сеть выглядит как
зависание.

### Лесенка строк — только на уровне Expressive

| | |
|---|---|
| Тайминг | 230 мс, сдвиг 16 мс, потолок 180 мс суммарно |
| Свойства | `opacity`, `transform.translation.y` −5 pt |
| Класс | C, ~0.9 мс на 20 строк |

**Не по умолчанию.** Анимировать можно только строки со своим `NSView`;
`Open Claude`, `Настройки`, `Quit` появятся сразу и не участвуют. Меню читается
как подтормозившее, а не как оживлённое. На уровне Subtle оживает не строка, а
её содержимое: шкалы, тумблеры, баннер.

## Правила

1. **Ни одного нового `Timer`.** Любая анимация — `CAAnimation`. Жест, который
   нельзя выразить через слой, не делается.
2. **Ноль работы при закрытом меню.** Все анимации одноразовые,
   `repeatCount` никогда не бесконечный. Единственное исключение — существующий
   спиннер проверки MCP.
3. **Reduce Motion уважается всегда.**
   `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` заменяет движение
   на кроссфейд, а не отключает его насухо: смена состояния должна оставаться
   видимой.
4. **Подсветка не догоняет курсор.** Вход мгновенный, анимируется только уход.
5. **Числа не врут по дороге.** Пружина на шкале — без перелёта: 93% не имеют
   права на миг показать 98%.
6. **Размер `NSVisualEffectView` не анимируется.** Прозрачность — можно,
   геометрию — нет: `.behindWindow` пересчитывает блюр каждый кадр.

пока её нет, каждая следующая фаза заводит собственные длительности, которые потом
нечем выключить.

Фаза 6 не сделана. Она продолжила бы уже существующую привычку репозитория рендерить
UI в изображение для ревью (`tools/crab-previews`, комментарий в `WhatsNew.swift` про
harness): ревьюер без Mac видел бы, что именно поменялось в движении. Пока такого
предпросмотра нет, изменения движения проверяются только на macOS руками.

## Как проверить

| Что | Как | Порог |
|---|---|---|
| Простой | `sudo powermetrics --samplers tasks -n 5 -i 1000`, меню закрыто | совпадает с текущим до шума измерения |
| Открытие меню | Instruments → Time Profiler, 30 открытий подряд, время в `menuNeedsUpdate` | рост ≤ 1.5 мс на открытие |
| Пропуск кадров | Instruments → Animation Hitches, проход по 20 строкам MCP | ноль hitch'ей |

Снимать до и после каждой фазы.
